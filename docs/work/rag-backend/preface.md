### 面试高频问题整理

#### 1. 你这个项目解决了什么问题？

这个项目主要解决团队内部结算知识分散、检索成本高、经验依赖口口相传的问题。以前设计文档、运维手册、异常处理指南都散落在不同位置，查找和复用效率很低。我做这个项目的目标，是把这些文档沉淀成一个可以上传、索引、检索、问答、返回来源的知识库系统，提升团队获取知识的效率。

#### 2. 为什么选 RAG，而不是直接把文档喂给大模型？

因为企业知识场景更强调基于内部资料回答、来源可追溯和内容可控。直接把问题发给大模型容易出现幻觉，而且没法保证回答基于最新文档。RAG 的价值在于先检索，再基于检索内容生成答案，同时把引用片段返回出来，这样可信度更高，也更适合企业内部使用。

#### 3. 为什么选 PostgreSQL + pgvector，而不是 Milvus 或 Elasticsearch？

因为项目第一阶段目标是先把最小可用闭环跑通，优先考虑系统简单、开发成本低和便于讲清楚。PostgreSQL 本身已经承载了知识库、文档、切块、任务和历史记录这些主数据，再加 pgvector 就能完成基础语义检索，不需要一开始就引入额外的向量数据库。后续如果数据量继续扩大，再考虑混合检索或引入专门的检索组件。

#### 4. 你的 RAG 主链路是什么？

主链路是：知识库创建 -> 文档上传 -> 文档解析 -> 文本切块 -> chunk 入库 -> embedding 写库 -> query embedding -> TopK 检索 -> Prompt 组装 -> 大模型回答 -> 返回答案和 sources -> 保存问答历史。

#### 5. 你的切块策略是怎么做的？

当前先用了固定窗口切块，并保留 overlap，同时尽量在自然断点附近切分。原因是第一阶段优先保证策略简单、行为稳定、容易验证。后面我又把切块参数外置，并做了 `compact / balanced / wide` 三组参数实验，对比 chunk 数、平均长度和长 chunk 分布，最后保留 balanced 作为默认折中方案。

#### 6. 为什么要做异步索引？

因为文档解析、切块和向量化是长链路操作，如果全部放在同步请求里，请求耗时会很长，失败时也不容易恢复。改成异步索引之后，前端拿到的是任务受理结果，后台再执行 process 和 embed，用户可以查看任务状态，也可以在失败后重试，这样更符合真实服务的设计。

#### 7. 你为什么还做了失败重试和卡住任务恢复？

因为异步任务一旦引入，系统真正的难点就不只是“能执行”，而是“失败后怎么办”。如果服务在处理中途退出，任务可能停留在 `QUEUED` 或 `RUNNING`。所以我补了两层机制：一层是失败任务支持手工重试，另一层是对长时间无心跳的任务做定时恢复扫描，避免任务长期卡死。

#### 8. `qa/readiness` 是做什么的？

它本质上是检索和问答前的门禁，不只是一个展示接口。它会统一检查知识库状态、chunk 是否完成索引、向量是否就绪、是否正在重嵌入。如果这些条件不满足，就直接阻断检索和问答请求，避免系统在“数据还没准备好”的情况下返回不可信的答案。

#### 9. 为什么要做 embedding profile 和重嵌入？

因为 embedding 模型、维度或者 provider 一旦变化，历史向量就可能和当前 query embedding 不兼容，继续检索会导致结果失真。所以我把 embedding 配置看成一个检索契约，当 profile 变化时，系统会显式标记需要重嵌入，并通过异步 rebuild 重新生成向量，保证检索结果一致。

#### 10. Redis 在这个项目里主要解决什么问题？

Redis 主要用于高频读路径加速，比如知识库详情、文档详情、chunk 列表、问答 readiness 和检索结果短 TTL 缓存。这样可以减少数据库和检索链路的重复开销。同时我还补了缓存失效策略和坏缓存自愈，避免脏缓存直接把接口打成 500。

#### 11. 你怎么验证这个系统是真实可用的，而不是只做了个 Demo？

我做了几类验证。第一类是端到端联调，已经跑通过 `md / txt / pdf` 三类文档从上传到问答历史的完整链路；第二类是切块参数实验，验证不同策略对 chunk 分布的影响；第三类是中文问答评测，已经基于真实样本文档完成一轮 6 条问题评测，其中 5 条可回答问题命中预期文档，1 条无答案问题返回兜底话术。

#### 12. 你觉得这个项目最像 AI 开发工程师的地方是什么？

我觉得不是“接了一个模型 API”，而是把模型能力做成了完整系统。我不只做了检索和问答，还做了数据建模、异步任务、缓存、恢复、配置治理、日志和评测。这说明我能把 AI 能力真正落到业务系统里，而不是只做一个演示原型。
